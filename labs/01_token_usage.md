# Token Usage

## Objective

Understand how Large Language Models (LLMs) measure work using tokens and learn how to programmatically retrieve token usage information from the OpenAI Responses API.

This experiment demonstrates that every interaction with an LLM produces valuable engineering metadata in addition to the generated response. Understanding this metadata is the first step toward building cost-efficient and production-ready AI applications.

---

# Engineering Question

How many tokens does an LLM consume for a given prompt, and why should an engineering team care?

---

# Why This Matters

Most developers focus on the textual response returned by an LLM.

In production systems, however, the response is only one part of the picture.

Every API call also returns operational metadata such as:

- Input tokens
- Output tokens
- Total tokens

These metrics form the foundation for:

- AI cost management
- Capacity planning
- Model comparison
- Prompt optimization
- Enterprise chargeback
- AI FinOps

If these metrics are ignored, organizations lose visibility into one of the largest operational costs of an enterprise AI platform.

---

# Background

Unlike traditional REST APIs that are billed per request, Large Language Models are primarily billed based on token consumption.

A token is a small unit of text processed by the model.

For example,

```
Enterprise AI Engineering
```

is not treated as one unit.

Instead, it is broken into multiple tokens before being processed.

Both the prompt submitted by the application and the response generated by the model consume tokens.

The OpenAI Responses API exposes this information through the `usage` object, making token consumption available for programmatic analysis.

# Program Flow

The program performs the following steps:

1. Read a prompt from a text file.
2. Invoke the OpenAI Responses API.
3. Receive the generated response.
4. Extract token usage metadata.
5. Display the response and engineering metrics.

# Engineering Observations

Several interesting observations can be made from this simple experiment.

- Every API response includes operational metadata in addition to the generated text.
- Token usage can be measured without additional instrumentation.
- Token usage becomes the foundation for pricing, scaling, and optimization.
- Engineering decisions should be based on measured token usage rather than assumptions.

Although this example is intentionally simple, the same information becomes extremely valuable in enterprise environments where applications may process millions of requests every day.

---

# Scaling Considerations

A single request consuming 250 tokens may appear insignificant.

An enterprise AI application serving one million requests per day would process hundreds of millions of tokens daily.

Without continuously monitoring token consumption, organizations may experience rapidly increasing operational costs without understanding the underlying cause.

This is why token measurement should be treated as a production metric rather than a debugging aid.

# Executive Corner

Engineering leaders often ask,

*"How much will our AI platform cost?"*

The more appropriate question is,

*"How many tokens are we consuming, why are we consuming them, and are we generating proportional business value?"*

Token consumption is not merely a technical metric—it is a business metric.

Organizations that continuously measure token usage are significantly better positioned to optimize cost, improve efficiency, and make informed model selection decisions.

---

# Key Takeaways

- Token usage is one of the most important operational metrics in enterprise AI.
- Every API response provides token metadata that should be captured and monitored.
- Token measurement forms the foundation for cost optimization and AI FinOps.
- Production engineering begins with measurement.
